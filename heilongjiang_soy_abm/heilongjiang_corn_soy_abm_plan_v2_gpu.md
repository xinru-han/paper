# 黑龙江玉米—大豆 ABM 研究方案 v2.0：GPU 加速可微分 ABM 升级版

> **版本**：v2.0（2026-07-06），与 v1.0（`heilongjiang_corn_soy_abm_plan.md`）配套使用
> **硬件**：NVIDIA T4（16GB 显存，CUDA）
> **定位**：v1 的计量校准 R 版 ABM 降级为 **Module R（基准与稳健性检验）**；主方法升级为"可微分 ABM + 贝叶斯模拟推断 + 省级合成人口 + 最优政策设计"
> **用途**：交由 Claude Code 按阶段执行

---

## 0. 执行总则（在 v1 §0 基础上增补）

1. **v1 的 Phase 0–3 是 v2 的强制前置**，一步不能省：数据盘点、面板构建、收益/补贴变量、计量估计——它们同时是 v2 深度模型的训练数据、SBI 校准的经验矩来源、以及可解释性的锚。v1 的三个停点（STOP-1/2/3）照常执行。
2. **v1 的 Phase 4–6（R 版 ABM）仍须完成**，编号改称 Module R。它承担三个角色：(a) 可微分 ABM 的正确性对照（Gate A 双实现互检）；(b) 论文的稳健性检验；(c) 模型比较表的基准行。
3. v2 新阶段编号 **G0–G6**，避免与 v1 冲突。
4. 新增停点：**⚠️STOP-4**（全省县级年鉴数据）、**⚠️STOP-5**（可选高风险模块取舍与期刊定位）。
5. **诚实条款**：v2 与 Module R 的所有结果差异必须完整呈现在模型比较表（G6）中，不得只报告对新方法有利的结果；每个"先进"组件都设 go/no-go 验收门（Gate A–D），过不了就降级为附录或砍掉，砍掉本身写入报告。
6. Python 侧随机性：`torch.manual_seed(20260706)`、`numpy` 同源 seed；GPU 完全确定性与性能有权衡（见 §4），验收结果一律用固定 seed 复现两遍。

## 1. 方法升级的定位与文献锚点

### 1.1 T4 显卡的真实价值（先说清楚，避免为用 GPU 而用 GPU）

| 用得上 | 用不上 |
|--------|--------|
| 深度选择模型训练（M1） | 千级 agent 的单次模拟（CPU 秒级即完） |
| SBI 归一化流训练与 1e4–1e5 次模拟系综并行（M4） | 计量估计本身（R/fixest 更合适） |
| 参数后验 × 情景 × MC 的三维并行推演（M5） | 常规图表 |
| **省级数百万 agent 合成人口模拟（M3）——GPU 的核心用武之地** | |
| 可微分 ABM 的端到端反向传播（M2） | |
| （可选）7–8B 量化 LLM agent 推理（M6，勉强可跑） | |

结论：让 GPU 从"加速器"变成"必需品"的设计是 **M3 省级扩展**——没有它，v2 的方法先进性成立但硬件必要性存疑。

### 1.3 论文叙事重排（四个卖点 + 一个锚）

1. **可微分 ABM 用于中国作物结构调整政策**（据检索确认新颖性）：政策弹性 ∂E[大豆份额]/∂补贴差 由自动微分**精确**给出，而非情景差分近似——弹性曲面本身是干净的方法贡献；
2. **贝叶斯 SBI 校准**：所有政策结论带完整后验预测区间，替代 v1 的矩匹配网格搜索 + ±1SE；
3. **省级合成人口扩展**：从 3 县约千户样本外推到全省全部农户的种植结构与财政总量测算，county 级用统计年鉴 2019–2024 玉豆面积做第二重校准/验证——这是从"样本县故事"升级为"省级政策工具"的关键，也是冲更高期刊的资本；
4. **最优政策设计**：从"情景网格"升级为"目标反解"——给定大豆份额目标，贝叶斯优化搜索最小财政成本的补贴组合，并给出"后验最差 10% 情形下仍达标"的稳健政策；
5. **锚**：Module R（计量 logit + R 版 ABM）全程作为可解释基准与稳健性支柱，回应"黑箱"质疑。

### 1.4 发表现实评估（诚实段，供 STOP-5 决策）

- **稳妥主攻**：*Agricultural Systems*（对方法创新最友好，可微分 ABM + SBI 在该刊几乎必然是首例级别）；备选 *Food Policy*（政策叙事重于方法）、*European Review of Agricultural Economics*；
- **上探条件**：若 G4 省级层完成、2022 事件验证与县级年鉴对齐都漂亮、且政策问题按"大豆进口替代/国家粮油安全"叙事拉满，可试 *Nature Food* / *Nature Sustainability* / *PNAS Nexus*；方法向可试 *Nature Computational Science*（但需把方法一般化、弱化黑龙江个案性）；
- **最大短板要直视**：微观行为参数只来自 3 县，Nature 系审稿人会紧盯"以 3 县外推全省"的可信度——G4 的捐赠者规则、积温带分层与县级对齐是唯一防线，方案里按"约束"而非"事后验证"来设计（§2-M3）；
- 结论：**按 Agricultural Systems 的完成度标准执行，按 Nature Food 的验证严格度自我要求**，投稿层级最后由结果质量决定（STOP-5 再议）。

## 2. 升级架构：六个模块

```
v1 Phase 0–3（数据+计量）──→ M1 行为层（logit ⊕ 深度选择模型）
                                    ↓
              M2 可微分 ABM 模拟器（PyTorch/CUDA，Gumbel-softmax）
               ↙            ↓                ↘
   Module R 对照     M4 SBI 贝叶斯校准      M3 省级合成人口
   （Gate A 互检）   （后验 → 不确定性带）   （县级年鉴对齐）
                            ↓
              M5 政策层：autodiff 弹性曲面 + 贝叶斯优化最优补贴设计
                            ↓
              G6 模型比较表 + 论文装配（M6 可选模块按 Gate D 取舍）
```

### M1 行为层：双引擎

- **引擎 A（v1 交付）**：Mundlak-CRE logit + fractional logit，系数、VCV、σ_a 已在 `behavior_params.json`。
- **引擎 B（新增）**：深度选择模型。
  - 结构：FT-Transformer（小配置）或带类别嵌入的 MLP，双头输出 {P(种大豆), E[份额|种]}；输入 = v1 的 X 全集 + Δm̂、Δŝ 分开进（保留补贴显著性检验的可比性）+ 县/年嵌入 + 滞后状态；
  - 训练规范（小样本纪律，户×年约 2,000–3,000 条）：模型参数量控制在 1e4–5e4；**时间块留出**（训练 ≤2022，验证 2023，测试 2024）；早停 + weight decay + dropout；类别不平衡用加权损失；全部超参搜索只在验证块上做；
  - 解释：SHAP + Δπ̂ 的部分依赖曲线，**必须做单调性检查**（补贴差增加而种豆概率下降的区段要报告并讨论，不许静默）；
  - **Gate B**：2024 测试块 AUC 与 Brier 不优于引擎 A（差值 ≤0）→ 引擎 B 降级为附录，主模拟用引擎 A。两引擎都过则主文并行报告。

### M2 模拟层：可微分 ABM（PyTorch/CUDA）

- 状态张量化：`S ∈ R^{B×N×K}`（B=参数/情景系综批，N=agent 数，K=状态维），村/县聚合用 `index_add_`/`scatter`，全程无 Python 级 agent 循环；
- 离散决策的可微松弛：种/不种用 **Gumbel-softmax**（温度 τ 从 1.0 退火至 0.1）+ straight-through estimator；份额头直接可微；
- **两种运行模式**：
  - `mode="diff"`：可微，用于梯度校准与 autodiff 弹性；
  - `mode="sample"`：硬采样（与 Module R 完全同构），用于政策模拟与对照；
- 年度时序、财政核算、冲击结构与 v1 §7.3–7.5 逐条一致（同一份设计文档，双实现）；
- **autodiff 政策弹性**：对补贴差、比价等杠杆张量开 `requires_grad`，一次反传得到全体 agent 的弹性，聚合成弹性曲面（分县/分组）；
- **Gate A（正确性互检，写入论文附录）**：同参数、同 seed 流下，`mode="sample"` 与 Module R（R 版）对比——6 年聚合大豆份额逐年差 < 0.5 个百分点、户级份额分布 KS 检验不拒绝。不通过则排查到通过为止，此项没有降级选项。

### M3 人口层：省级合成农户群体（GPU 核心场景）

- **数据需求（⚠️STOP-4，请用户提供或授权联网检索后复核）**：
  1. 黑龙江分县（约 70+ 县市区）乡村户数/农业经营户数（普查或年鉴）；
  2. 分县玉米、大豆播种面积 2019–2024（统计年鉴/统计公报）；
  3. 可得的经营规模分布信息（如农业普查分规模户数，哪怕全省层面）；
  4. 分县积温带归属表（农业气候区划，公开资料）。
- 方法：
  - **捐赠者规则**：每个目标县按积温带匹配到调查县（一带→大箐山型，二/三带→桦南型，一带南部/松嫩平原→双城型），agent 特征从对应调查县的经验分布抽样；
  - **IPF/最大熵再加权**：对齐县级边际（户数、玉豆总面积、可得的规模分布）；初始 s_i 对齐该县 2024 年实际玉豆份额；
  - 规模：全省玉豆种植户量级为数百万，float32 下 3M agents × 30 状态维 ≈ 0.36 GB，系综批 B=16–32 完全在 16GB 预算内（详表见 §4）；
- **县级对齐既是约束也是验证**：2019–2023 县级年鉴份额用于约束再加权，**2024 留出不参与拟合、只做验证**；
- 输出：省级大豆面积份额路径、全省财政总量（亿元）、分积温带异质性——这一层是政策报告的主体。
- 若 STOP-4 数据不可得：v2 收缩为"样本县可微分 ABM + SBI"，仍成立，但 §1.4 上探选项作废，须在 PROGRESS.md 明记。

### M4 校准层：双轨（梯度矩匹配 + SBI 神经后验估计）

- **轨 1：梯度矩匹配（快速点估计）**——`mode="diff"` 下最小化加权矩距离（矩集合同 v1 T5.1，另加"2022 年份额跳升幅度"作为关键矩），Adam 优化，分钟级收敛；作为 SBI 的初值与 sanity check。
- **轨 2：SNPE（主结果）**——`sbi` 包，Neural Posterior Estimation（掩码自回归流）：
  - 待推参数：{β 系（以计量估计为中心的宽先验，如 N(β̂, 3·SE)）, λ_e, δ_rot, δ_rep, 冲击尺度 σ_p/σ_y/σ_macro}，维度约 10–15；
  - 摘要统计：分县×年参与率、s 均值、进入/退出转移率、2022 跳升、份额分布分位数（约 40–60 维）；
  - 模拟预算：1e4–1e5 次，GPU 系综一批 256–1024 条并行，小时级完成；
  - 诊断：**SBC（simulation-based calibration）检查** + 后验预测检查（PPC）必做；
  - 输出：联合后验样本 → 下游一切政策结果都以"后验 × MC"双层不确定性呈现（这是对 v1 ±1SE 的实质升级）。
- 摘要统计选择的主观性：准备两套统计集做敏感性（见 §6）。

### M5 政策层：从情景网格到最优设计

1. **弹性曲面（autodiff）**：∂E[大豆份额]/∂(大豆补贴)、∂/∂(玉米补贴)、∂/∂(轮作补贴)、∂/∂(豆粮比价)，分县/分规模/分年龄组输出——直接回答"什么情况下种玉米/种大豆的概率如何变"；
2. **v1 情景矩阵 S0–S5 全部保留复跑**（保证与 Module R 结果可比）；
3. **目标反解（新增主结果）**：BoTorch 贝叶斯优化，决策变量 =（大豆补贴增量, 玉米补贴增量, 轮作补贴, 覆盖率），目标 = 最小化省级财政增量支出，约束 = E_posterior[大豆份额提升] ≥ {+5pp, +10pp}（约束以惩罚或可行域筛选处理），期望对 M4 后验取平均；
4. **稳健政策**：额外报告"在后验最差 10% 分位情形下仍达标"的政策组合（政策制定者视角的保险方案）；
5. **（可选，M6 联动）AI Economist 式双层框架**：外层规划者 RL 调补贴、内层农户适应——作为 stretch goal，见 M6。

### M6 可选高风险模块（Gate D 统一把关）

- **M6a 适应性学习农户（应对卢卡斯批判）**：估计出的决策规则隐含"政策大幅变化下行为参数不变"的假设；本模块让 agent 用强化学习更新选择倾向——先做无深度的 **Roth-Erev / EWA 经验加权学习**（经济学审稿人熟悉、可解释），深度 RL（小 MLP policy，PPO）作对照。
  - Gate D-a：学习型 agent 复现 2022 事件与 2024 留出的精度**不劣于**基准引擎，且学习参数可辨识 → 进主文一节；否则附录。
- **M6b LLM 农户 agent（探索性）**：T4 仅能跑 7–8B int4 量化（约 5GB 显存，吞吐低）；只做 ≤200 agent、3 个情景的定性探索——中文 prompt 注入农户画像（年龄/规模/兼业/县域）+ 当年价格补贴信息，抽取种植意向，与计量引擎的预测概率对比一致性。
  - Gate D-b：与观测行为的一致性达不到基准水平（预期大概率如此）→ 仅作一段"生成式 agent 探索"的附录讨论或完全删除。**默认不进主文，不为蹭热点牺牲论文可信度。**
- ⚠️STOP-5：G3 完成后，与用户共同决定 M6a/M6b 取舍及目标期刊（影响写作重心与篇幅分配）。

模型比较表本身回答一个审稿人必问的问题——"方法上的复杂化到底买来了多少预测力与政策洞见"——**无论答案偏向哪边都是可发表的结果**，这是 v2 设计的保险栓。

## 4. 工程规范（T4 / 16GB 专用）

- **环境**：CUDA 12.x + PyTorch 2.x；`sbi`、`botorch`、`shap`、`polars/pandas`、`pyarrow`（与 R 侧经 parquet/JSON 交换，接口沿用 `behavior_params.json`）；
- **精度策略**：模拟器一律 **float32**（数值稳定优先；T4 无 bf16，fp16 只用于神经网络训练的 AMP，不用于模拟器状态）；
- **显存预算表（写入 G0 报告并实测校正）**：

| 组件 | 规模 | 估算显存 |
|------|------|----------|
| 省级 agent 状态 | 3M × 30 维 × fp32 | ~0.36 GB |
| 系综批 B=16 | 16 × 3M × 30 | ~5.8 GB |
| Gumbel/中间激活 | ~1 生命周期 step | ~2–4 GB |

## 6. 风险与诚实声明（预写审稿人回应）

- **小样本 × 深度模型过拟合**：时间块留出是硬约束；引擎 B 过不了 Gate B 就退场，主文永远保留可解释的引擎 A；
- **Gumbel 松弛偏差**：τ 敏感性网格 + `sample` 模式复核关键结果；Gate A 保证硬采样路径与 R 版一致；
- **SBI 摘要统计选择主观**：两套统计集（含/不含分布分位数）敏感性 + SBC 诊断入附录；
- **"以 3 县外推全省"**：这是全文最脆弱的环节，防线三层——捐赠者规则按积温带显式声明、县级年鉴对齐作为拟合约束（非事后自夸）、2024 县级留出作诚实检验；正文明确标注哪些结论是"样本县内证据"、哪些是"模型外推"；
- **黑箱质疑**：双引擎并行 + SHAP/PD + Module R 全程对照 + G6 比较表；
- **M6 审稿风险**：默认附录；LLM agent 若一致性差直接删除，删除记录保留在 PROGRESS.md（对自己诚实）；
- **算力叙事风险**：论文不以"用了 GPU"为卖点，卖点是方法与政策结论，GPU 只在计算附录出现。
